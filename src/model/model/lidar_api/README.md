# lidar_api — поиск скоплений на кадре лидара

Одна функция: на вход кадр лидара как `.npy`, на выход JSON. В нём сказано, в каких
блоках дальности (0–100, 100–200, 200–300 м) нашлось скопление, а в каких нет, и на
каком расстоянии. Визуализации здесь нет.

Папка самодостаточная: код детектора и веса внутри, от остального репозитория ничего
не нужно. Логика и пороги — те же, что в `inference/`.

```
lidar_api/
├── api.py               analyze() / analyze_json() - это и вызывает бэкенд
├── lidar_detector/      детектор: U-Net + поиск скоплений (внутренности)
├── artifacts/           веса модели и таблицы - без них не запустится
│   ├── model.pt
│   ├── elevation.npy, structural_empty.npy, added_rate.npy
│   ├── cluster_zones_3d.json   пороги поиска скоплений
│   └── meta.json
└── requirements.txt     numpy, torch
```

## Установка

Python 3.10+:

```bash
pip install -r requirements.txt
```

Для видеокарты — torch со сборкой CUDA (`pip install torch --index-url https://download.pytorch.org/whl/cu130`).
Без видеокарты тоже работает, но медленнее.

## Вызов

```python
import sys
sys.path.insert(0, "путь/к/lidar_api")
from api import analyze, analyze_json

info = analyze("frame.npy")        # путь к .npy
info = analyze(points)             # numpy-массив
info = analyze(npy_bytes)          # байты .npy-файла, например тело HTTP-запроса
text = analyze_json(points)        # сразу строка JSON
```

Модель грузится один раз при первом вызове (~1–2 с) и дальше переиспользуется.
Один кадр — **~80 мс** на RTX 2060 SUPER. Вызывать можно из нескольких потоков:
кадры встают в очередь к одной модели.

Проверка из командной строки:

```bash
python api.py D:\metro_test\cloud_with_fake_obj\points\000150.npy
```

### Вход

Облако точек одного кадра:
- `(N, 4)` — `x, y, z, intensity` (как в `D:\dataset_numpy\...\points\*.npy`);
- `(N, 5)` — плюс номер луча `ring` (0..127);
- structured array с полями `x, y, z, intensity` (и, если есть, `ring`).

Нулевые точки (луч не вернулся) и точки с NaN пропускаются сами. Пустой массив —
допустимый вход, ответ будет «ничего не найдено». Массив другой формы — `ValueError`.

### Ответ

```json
{
  "detected": 1,
  "blocks": [
    {"block": "0-100",   "from_m": 0,   "to_m": 100, "detected": 1, "clusters": 1, "nearest_m": 61.57},
    {"block": "100-200", "from_m": 100, "to_m": 200, "detected": 0, "clusters": 0, "nearest_m": null},
    {"block": "200-300", "from_m": 200, "to_m": 300, "detected": 0, "clusters": 0, "nearest_m": null}
  ],
  "clusters": [
    {"id": 1, "block": "0-100", "distance_m": 61.57, "distance_min_m": 60.84,
     "center": [0.108, -61.332, -0.605], "min": [-0.699, -61.833, -1.427], "max": [0.914, -60.83, 0.217],
     "size_m": 1.644, "extent_m": [1.613, 1.002, 1.644], "points": 18}
  ],
  "frame": {"points_in": 62660, "points_out": 62942, "added": 300},
  "time_ms": 79.7
}
```

| поле | что это |
|---|---|
| `detected` | 1 — скопление есть хотя бы в одном блоке, 0 — нигде |
| `blocks[].block` | блок по дальности от лидара: `0-100`, `100-200`, `200-300` м |
| `blocks[].detected` | 1 — в этом блоке есть скопление, 0 — нет |
| `blocks[].clusters` | сколько скоплений в блоке |
| `blocks[].nearest_m` | расстояние до ближайшего скопления в блоке, м; `null`, если скоплений нет |
| `clusters[]` | все скопления кадра, от ближнего к дальнему |
| `clusters[].block` | в каком блоке скопление |
| `clusters[].distance_m` | расстояние от лидара до скопления (медиана по его точкам), м; по нему выбирается блок |
| `clusters[].distance_min_m` | расстояние до ближайшей точки скопления, м |
| `clusters[].center`, `min`, `max` | центр и углы рамки, м |
| `clusters[].size_m`, `extent_m` | самая длинная сторона рамки и размеры по x, y, z, м |
| `clusters[].points` | сколько точек в скоплении |
| `frame` | точек во входе, в ответе модели и сколько модель добавила |
| `time_ms` | время обработки кадра, мс |

Система координат — лидара, в метрах: `z` вверх, вперёд по тоннелю — `-y`, влево — `+x`.

Блок включает нижнюю границу и не включает верхнюю: скопление на 100,0 м попадёт в
`100-200`. Скопления дальше 300 м не ищутся. Блоки задаются списком `BLOCKS` в `api.py`.

## Что ищется

Нейросеть U-Net восстанавливает кадр: достраивает дыры, поправляет дальности, убирает
мусор. Скопление — плотная группа точек, которые модель **добавила** (во входе на этом
месте пусто, а в ответе точка есть). Пороги (радиус соседства, сколько точек нужно,
размер, толщина, фильтр «привычек» модели) задаются по зонам дальности 0–50, 50–100, …
250–300 м в `artifacts/cluster_zones_3d.json`. Их удобно подбирать в просмотрщике
`inference/viewer`, а потом скопировать файл сюда.

Скопление — кандидат на посторонний предмет, а не класс: детектор не говорит, что это
за предмет.

## Качество

Проверка на записи `cloud_with_fake_obj` со вставленными предметами (каждый 10-й кадр,
151 кадр): скопление найдено в 42 кадрах, из них 38 — в блоке 0–100 м, 8 — в 100–200 м,
0 — в 200–300 м (в одном кадре скопления могут быть в нескольких блоках). По прежней
проверке (`inference/README.md`) 87% найденных скоплений лежат на вставленном предмете,
но примерно половину кадров с предметом детектор пропускает, и в ~16% кадров без
предмета всё же находит скопление. Чаще всего ложные — маленькие скопления (6–10 точек)
на 50+ м.
