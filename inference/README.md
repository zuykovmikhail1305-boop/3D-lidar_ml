# Детектор скоплений на кадрах лидара

По одному кадру лидара (облако точек) находит в тоннеле посторонние предметы. Нейросеть U-Net восстанавливает «чистый» кадр: достраивает дыры, поправляет дальности, убирает мусор. Там, где модель добавила точки, которых не было во входе, в объёме ищутся скопления. Скопление — кандидат на посторонний предмет, для каждого отдаются центр, размеры и рамка в метрах.

Папка самодостаточная: весь код и веса внутри, от остального репозитория ничего не нужно.

```
inference/
├── lidar_detector/          пакет Python - это и нужно встраивать в бэкенд
│   ├── detector.py          Detector (главный класс), Result, Bag
│   ├── model.py             U-Net и прогон кадра через неё
│   ├── clusters.py          поиск скоплений в объёме
│   ├── range_image.py       облако <-> развёртка 128 x 1024, рабочий сектор
│   └── rosbag.py            чтение rosbag2 (.db3) и разбор PointCloud2 без ROS
├── artifacts/               веса и таблицы - без них детектор не запустится
│   ├── model.pt             веса U-Net (31 МБ)
│   ├── elevation.npy        угол места каждого из 128 лучей лидара
│   ├── structural_empty.npy пиксели, пустые у лидара всегда
│   ├── added_rate.npy       «привычки» модели: где она добавляет точки постоянно
│   ├── cluster_zones_3d.json пороги поиска скоплений по зонам дальности
│   └── meta.json            откуда веса, параметры развёртки и сектора
├── run_bag.py               запись rosbag2 -> CSV/JSONL со скоплениями
├── viewer/                  визуализация: кадр до и после модели, скопления в рамках
├── calibrate.py             пересчитать added_rate.npy после смены весов
├── export_weights.py        перенести новые веса из обучения в artifacts/model.pt
└── requirements.txt
```

## Установка

Python 3.10+, зависимости — только numpy и torch:

```bash
pip install -r requirements.txt
```

Для видеокарты нужен torch со сборкой CUDA, например:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu130
```

Без видеокарты тоже работает, но медленнее (см. «Скорость»).

## Быстрый старт

### Из кода

Запускать из папки `inference` или добавить её в `PYTHONPATH`.

```python
from lidar_detector import Detector

det = Detector()                         # один раз: грузит веса и таблицы из artifacts/
res = det.process_points(points)         # на каждый кадр

for c in res.clusters:
    print(c["center"], c["extent_m"], c["points"])

res.detected                             # 1 - в кадре есть скопление, 0 - нет
det.detect(points)                       # то же одной строкой: сразу 1 или 0
```

`det.detect(...)` принимает то же облако, что `process_points`, или сырое сообщение PointCloud2 в байтах.

`points` — облако одного кадра, в одном из видов:
- numpy-массив `(N, 4)`: `x, y, z, intensity`;
- `(N, 5)`: плюс номер луча `ring` (0..127);
- numpy structured array с полями `x, y, z, intensity` и, если есть, `ring` — так его отдаёт `rosbag.parse_pointcloud2`.

Нулевые точки (луч не вернулся) можно не убирать, они пропускаются сами. Если `ring` нет, номер луча восстанавливается по углу места точки.

Есть и другие входы:

```python
res = det.process_message(blob)                  # сырое сообщение sensor_msgs/PointCloud2 (CDR-байты, как в rosbag2)
res = det.process_images(range_in, intensity_in) # уже готовая развёртка 128 x 1024
```

### Запись целиком

```bash

```

Результат ляжет в `results/<имя записи>/`:

| файл | что внутри |
|---|---|
| `clusters.csv` | по строке на скопление: кадр, время, зона, точки, размеры, центр, рамка |
| `frames.csv` | по строке на кадр: `detected` (1 / 0), точек во входе и в ответе, добавлено, скоплений |

### Визуализация

```bash
python viewer/server.py D:\hackaton_full_dataset\cloud_with_fake_obj
```

Откроется страница `http://127.0.0.1:8790/`: слева кадр до модели, справа после, найденные скопления обведены рамками на обеих панелях. Кнопка «зоны» открывает пороги поиска, «сохранить» записывает их в `artifacts/cluster_zones_3d.json`, и с этого момента их использует `Detector`. Кнопки «◀ скопление» / «скопление ▶» (клавиши `[` `]`) переходят к кадрам со скоплениями. Мышь вращает обе панели сразу, ← → листают кадры.

## Что возвращает `Result`

| поле | тип | что это |
|---|---|---|
| `detected` | `int` | 1 — в кадре найдено хотя бы одно скопление, 0 — нет |
| `clusters` | `list[dict]` | найденные скопления, см. ниже |
| `range_in` | `float32 (128, 1024)` | вход модели, м; 0 — пусто. Уже обрезан по рабочему сектору |
| `intensity_in` | `float32 (128, 1024)` | интенсивность входа, 0..255 |
| `range_out` | `float32 (128, 1024)` | ответ модели, м; 0 — точки нет |
| `occupancy` | `float32 (128, 1024)` | вероятность «здесь есть точка» |
| `junk` | `float32 (128, 1024)` | вероятность «входная точка — мусор» |
| `labels` | `int32 (128, 1024)` | номер скопления пикселя, 0 — не скопление |
| `added` | `bool (128, 1024)` | добавленные моделью пиксели, по которым шёл поиск |
| `points_in()` | `(N, 4)` | вход точками: `x, y, z, intensity` |
| `points_out()` | `(N, 5)` | ответ модели точками: `x, y, z, added (0/1), cluster_id` |

Одно скопление (`dict`):

| ключ | пример | что это |
|---|---|---|
| `id` | `1` | номер в кадре, совпадает с `labels` |
| `zone` | `0` | номер зоны дальности в `det.zones` |
| `points` | `1197` | сколько добавленных моделью точек в скоплении |
| `center` | `[0.4, -2.9, -0.3]` | центр рамки, м |
| `min`, `max` | `[..]`, `[..]` | углы рамки (выровнена по осям), м |
| `extent_m` | `[1.12, 1.69, 0.46]` | размеры рамки по x, y, z, м |
| `size_m` | `1.69` | самая длинная сторона рамки, м |
| `range_m` | `2.98` | медианная дальность точек скопления от лидара, м |
| `voxels` | `412` | сколько кубиков 5 см занимает |

**Система координат** — лидара, в метрах: `z` вверх, вперёд по тоннелю — `-y`, влево — `+x`, вправо — `-x`.

## Как это устроено

1. **Облако → развёртка 128 × 1024.** Строка — луч лидара (ring 0 сверху, +14,4°; ring 127 снизу, −25,1°). Столбец — азимут от −141,2° с шагом 0,1°. Значение — дальность. Если в пиксель попадает несколько точек (два эха), остаётся ближняя.
2. **Рабочий сектор.** Лидар видит азимуты −140…−40° (по 50° влево и вправо от «вперёд»). С каждого края срезается по **17°**, остаётся −123…−57° (66°, 660 столбцов). Эти точки модель не видит ни при обучении, ни здесь, и скопления там не ищутся. Настройка — `CUT_LEFT` / `CUT_RIGHT` в `range_image.py`; менять её надо только вместе с переобучением.
3. **U-Net** получает 4 канала (дальность, интенсивность, занятость, дыры, залитые ближайшей точкой слева) и отдаёт поправку дальности, «точка есть» и «точка — мусор». Итоговый ответ: точка есть там, где «точка есть» > 0,5 и входная точка не признана мусором.
4. **Добавленные точки** — пиксели, где во входе пусто, а у модели есть дальность. Не рассматриваются:
   - места, где лидар пуст всегда (у крайних лучей он пишет только каждый второй столбец) — `structural_empty.npy`;
   - «привычки» модели — пиксели, куда она добавляет точки из кадра в кадр (`added_rate.npy`).
5. **Поиск в объёме.** Добавленные точки переводятся в x, y, z и прореживаются кубиками 5 см. Соседи — точки ближе радиуса. Радиус растёт с дальностью, потому что вдали точки лидара стоят реже. Скопление — связная группа соседей, прошедшая пороги своей зоны.

## Пороги по зонам дальности

Файл `artifacts/cluster_zones_3d.json`. Зоны по умолчанию: 0–50, 50–100, … 250–300 м. Точка относится к зоне по своей дальности.

| параметр | по умолчанию | что делает |
|---|---|---|
| `enabled` | `true` | искать ли в зоне вообще |
| `radius` | `0.15` | наименьший радиус соседства, м; дальше растёт на 1 см на метр дальности |
| `min_points` | `200` (0–50 м), `6` дальше | сколько точек нужно скоплению в начале зоны (для первой зоны — с 2 м); дальше порог падает как 1/r², но не ниже 6 |
| `min_size` | `0.1` | самая длинная сторона рамки не меньше, м |
| `max_size` | `6.0` | и не больше, м: длиннее — уже полоса вдоль стены, а не предмет |
| `min_thickness` | `0.1` | самая короткая сторона рамки не меньше, м: плоский кусок стены или пола отсекается |
| `habit` | `0.2` | не искать там, где модель добавляет точки чаще этой доли кадров; `0` — искать везде |

Подбирать пороги удобнее всего в визуализации. Из кода: `det.zones = [...]` или `det.process_points(points, zones=[...])`.

## Скорость

Замер на RTX 2060 SUPER + i5-10400F, один кадр ~300 тыс. точек:

| этап | время |
|---|---:|
| облако → развёртка (с восстановлением `ring`) | ~50 мс |
| U-Net на видеокарте | ~13 мс |
| поиск скоплений | ~5–20 мс |
| **итого** | **~70–90 мс, ~11–14 кадр/с** |

На процессоре U-Net занимает сотни миллисекунд на кадр. Если читать кадры из файла записи на HDD, чтение в произвольном порядке добавляет до ~300 мс на кадр; на потоке с лидара этого нет.

## Качество сейчас

Веса — **вторая эпоха обучения** (`meta.json`), это ранняя модель. Проверка на записи `cloud_with_fake_obj` со вставленными предметами, каждый 10-й кадр. «Правильный ответ» — точки, которые не лежат на углах лучей лидара (сенсор так не пишет, значит их вставили):

| | |
|---|---:|
| скоплений, которые лежат на вставленном предмете | **87%** |
| кадров без вставленных предметов, где всё же нашлось скопление | 16% (0,19 ложных на кадр) |
| кадров со вставленным предметом, где нашлось скопление | 46% |

То есть найденному скоплению можно верить, но примерно половину кадров с предметами детектор пока пропускает. Это ограничение модели: с дальнейшим обучением оно должно уменьшаться. Код детектора при смене весов менять не нужно.

## Смена весов

После нового обучения (файлы `runs_unet/epoch_XXX_*.pt` в основном репозитории):

```bash
python export_weights.py ..\runs_unet\epoch_005_train_loss_0.0312.pt
```

```bash
python calibrate.py D:\hackaton_full_dataset\cloud_with_fake_obj
```

Первая команда кладёт в `artifacts/model.pt` только модель (без оптимизатора). Вторая пересчитывает `added_rate.npy`: «привычки» у каждой модели свои. Старые файлы сохраняются рядом как `.bak`.

## Что важно знать

- **Лидар.** Всё настроено на Hesai 128 из этих записей: 128 лучей, углы лучей из `elevation.npy`, сектор −140…−40°. Для другого лидара или другой установки нужно пересчитать таблицы и переобучить модель.
- **Потоки.** Один `Detector` держит модель на видеокарте. Из нескольких потоков вызывайте его под блокировкой или создайте по экземпляру на поток.
- **Граница зон.** Соседи ищутся внутри зоны, поэтому предмет ровно на 50 м может распасться на два скопления.
- **Скопление — кандидат, а не класс.** Детектор не говорит, что это за предмет; он говорит, что здесь модель увидела то, чего не было во входе.
- **Веса в git.** `model.pt` весит 31 МБ, это меньше лимита GitHub (100 МБ). Если веса будут часто меняться, их лучше вести через Git LFS.
